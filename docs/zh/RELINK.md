# 明确移动后重新关联缺失的照片

`python database.py --relink-photos` 会在你自行移动文件之后，更新 Facet 数据库中已有的路径。它绝不会移动、复制、删除或编辑原图及附属文件，也绝不会联系 Immich。这是一个离线维护命令，面向能够访问数据库和已配置文件夹的操作员。请先停止查看器、扫描器和外部文件编辑器；备份数据库，并在应用前审核计划。

应用操作在整个数据库写入期间持有 Facet 的照片库维护锁。其他照片库任务正在运行时，退出码为 75，数据库和媒体都不会改变；锁无法使用时，退出码为 1。预览保持只读，不获取照片库锁。该锁只协调同一主机上的任务；离线要求对其他主机和外部编辑器仍然适用。

现有数据库没有原始文件字节的密码学哈希。`phash` 和手工人脸的灰度签名都无法证明字节级一致。因此每个计划都会标注 `original_bytes_unknown`。目标的 SHA-256 只标识已预览的新文件。应用即表示你明确声明已通过其他方式确认了正确的已移动文件；这从来不是自动验证的匹配。错误的声明可能把现有标注关联到错误的图像上。

当旧的上级目录已不存在时，移动或重命名整个目录超出了这一受限模式的范围。缺失的目录无法区分是有意移动还是存储离线。请勿通过重新创建空的旧上级目录来绕过此检查。

## 预览、审核，然后应用

创建一个包含精确规范绝对路径的 JSON 列表。缺失的源文件必须已在 Facet 中登记；目标必须作为图像存在，且尚无照片记录：

```json
[
  {
    "old": "/photos/before/portrait.jpg",
    "new": "/photos/after/portrait-renamed.jpg",
    "companions": [
      {
        "old": "/photos/before/portrait.jpg.xmp",
        "new": "/photos/after/portrait-renamed.jpg.xmp",
        "kind": "sidecar_full"
      }
    ]
  }
]
```

```sh
# 只读的数据库预览；创建一个私有（0600）且独占的审核文件。
python database.py --relink-photos --db library.db --config scoring_config.json \
  --mapping moved.json --plan-out relink-plan.json

# 在 relink-plan.json 中检查每个新旧路径、字节未知的身份标签、目标哈希、尺寸、
# 引用、伴随文件和可见性策略。
# 审核后，将 REVIEWED_PLAN_ID 替换为该文件中准确的 plan_id。
python database.py --relink-photos --db library.db --config scoring_config.json \
  --apply-plan relink-plan.json --ack-plan REVIEWED_PLAN_ID \
  --acknowledge-unverified-identity
```

多用户模式在两条命令中还都需要 `--user alice`。它是面向操作员的范围选择器，既不能替代操作系统的访问控制，也不是经过认证的 API。两条路径对该用户都必须可见，且能够看到该照片的**所有**用户的集合必须保持不变。从私有移到共享，或其他跨用户移动，均会被拒绝。两条路径都必须位于明确配置的扫描、用户或共享目录内。空白的根目录配置、无法访问的根目录以及 `viewer.path_mapping` 均会被拒绝；这个初始工具只支持本机规范路径。

应用操作会在同一个 SQLite 写事务内重新检查整个已审核的计划。目标文件、照片记录、标注、数据库结构、数据库 inode 或可见性策略一旦变化，就需要重新预览。批次失败时，其所有数据库写入都会回滚。应用成功后会输出带有计划 ID 的回执。它不会存储新的逻辑资源 ID 或远程 UUID 映射。

## 哪些内容会随照片保留

照片 rowid、评分/Keep/GPS、标签、人脸/人物 ID 和手工 UUID、比较记录、学习得分、各用户偏好、覆盖设置、固定的相册成员/封面/客户挑选、提取快照以及向量嵌入都会保留各自的关联。现有指向 photos 的外键从真实的数据库结构中发现；新增的未登记路径列会被拒绝，而不是被悄悄遗留为孤儿。派生统计会失效；持久的训练状态则会保留。

整理历史条目保留其原始的历史路径内容。现有的路径变更触发器会推进修订时钟并使私有修订缓存失效；指向旧路径的条目在重新关联后可能不再显示，也可能无法再还原。重新关联会保留当前的标注值和关联，但不会改写过去的操作，使其适用于另一条路径。

所有手工矩形框都会保留，但需要在新路径上重新审核。粗略的旧签名无法证明缺失原图的像素内容。`relink_unverified` 标记会阻止常规签名检查清除这一审核状态；请打开编辑器，并针对新画面逐个明确保存每个矩形框，之后它才能被导出或用于抑制检测结果。现有的矩形框和人物 ID 会保留。

Immich 的推送/待处理状态保持不变：本地文件名声明无法验证远程身份。不会重新关联任何远程评分、清除操作、相册成员或 UUID。同步之前请单独检查远程映射。历史扫描失败路径保持为历史记录；智能相册的筛选条件和逻辑序列组键不会被悄悄改写。静态成员以及序列/连拍/重复组的值保持不变。

## 明确列出的伴随文件与拒绝情形

请明确列出伴随文件；该工具无法发现已从旧目录消失的未索引 RAW/XMP 文件。`sidecar_full` 表示 `photo.ext.xmp`，`sidecar_basename` 表示 `photo.xmp`，`sidecar_facet` 表示 `photo.ext.facet.xmp`，`raw` 则保留明确提供的、位于同一目录且主文件名相同的 RAW 配对，使其与当前的筛选流程兼容。这些文件名规则只验证所声明的关系，并不证明文件身份。已索引的 RAW 照片需要有各自的顶层重新关联条目，其标注才能得到保留。

目标位置上未列出的附属文件或 RAW 伴随文件会被拒绝，包括 Facet 回退包和大小写变体。多个 RAW 候选以及归属不明的 XMP 会被拒绝，包括 `IMG.CR2` + `IMG.CR2.jpg` + `IMG.CR2.xmp`、`IMG.CR2` + `IMG.CR2.facet.jpg` + `IMG.CR2.facet.xmp`，以及基本名、大小写或 Unicode 冲突。不会按先找到的匹配项分配任何伴随文件。现有伴随文件的字节会被哈希并复查，且保持不变。未列出的缺失伴随文件仍然未知；请勿把空列表理解为证明不存在此类文件。

以下情形会被拒绝：旧原图仍然存在的副本，缺失或不可读的旧上级目录，已存在的目标照片或依赖记录，重复的映射，重复的照片内容或目标 inode，仅大小写或仅 Unicode 的变化，符号链接，以及扩展名或格式的变化。已知时，存储的规范尺寸必须与解码后的目标一致。不会运行任何相似度或文件名搜索，也不会进行自动对账。

限制：100 张照片、300 个明确列出的文件、每个文件 512 MiB、文件字节总计 2 GiB，以及 2 MiB 的 JSON 输入或审核计划。达到限制时请减小批次。数据库事务是原子的；文件系统不会针对其他应用被锁定，因此才有离线要求。夹具测试并不声称已与真实的外部应用或远程服务器完成往返验证。

目录可读**并不**能证明存储已挂载。未挂载的卷可能留下一个为空但可读的挂载点，与移动后真正为空的目录无法区分。计划会明确报告 `source_mount_status: not_verified`；在确认身份之前，请独立确认每个源文件确实已被移动，而不仅仅是不可用。该命令不会检测所有离线卷的情形。审核计划包含私密的完整路径和用户范围策略；`--plan-out` 会以独占方式创建它们，在 POSIX 上权限为 0600。

| 选项 | 用途 |
|---|---|
| `--db` | 现有数据库 |
| `--config` | 解析后的配置 |
| `--user` | 多用户模式下必须指定已配置用户 |
| `--mapping` | 显式旧/新路径 JSON；预览模式 |
| `--plan-out` | 创建新的私密计划文件，不覆盖已有文件 |
| `--apply-plan` | 应用已审核的计划 |
| `--ack-plan` | 已审核计划的准确摘要 |
| `--acknowledge-unverified-identity` | 明确确认原图字节身份未知的操作 |
