# 明确移动后重新关联缺失的照片

`python database.py --relink-photos` 会在你自行移动文件之后，更新 Facet 数据库中的路径。它绝不会移动、复制、删除或编辑原图及附属文件，也绝不会联系 Immich。这是一个离线维护命令。

应用计划之前：

- 停止查看器、扫描器和外部文件编辑器。
- 备份数据库。
- 审核计划。

应用操作会获取 Facet 的照片库锁。其他照片库任务正在运行时，退出码为 75，且不会改变任何内容；锁无法使用时，退出码为 1。预览是只读的，不获取锁。该锁只涵盖同一主机上的任务。

> **警告：** Facet 不存储原始文件字节的哈希，因此无法证明新文件就是被移动的那个文件。每个计划都会标注 `original_bytes_unknown`；`phash` 和手工人脸的签名都无法证明身份一致。目标的 SHA-256 只标识你预览过的文件。应用即表示你声明已自行核对过匹配。错误的声明会把现有标注关联到错误的图像上。

当旧的上级目录已不存在时，不支持移动或重命名整个目录。请勿通过重新创建空的旧上级目录来绕过此检查。

## 预览、审核，然后应用

创建一个包含精确规范绝对路径的 JSON 列表。每个源文件都必须已在 Facet 中登记。每个目标都必须作为图像存在，且尚无照片记录：

```json
[
  {
    "old": "/photos/before/portrait.jpg",
    "new": "/photos/after/portrait-renamed.jpg",
    "companions": [
      {
        "old": "/photos/before/portrait.jpg.xmp",
        "new": "/photos/after/portrait-renamed.jpg.xmp",
        "kind": "sidecar_full"
      }
    ]
  }
]
```

```sh
# 只读的数据库预览；创建一个私有（0600）且独占的审核文件。
python database.py --relink-photos --db library.db --config scoring_config.json \
  --mapping moved.json --plan-out relink-plan.json

# 在 relink-plan.json 中检查每个新旧路径、字节未知的身份标签、目标哈希、尺寸、
# 引用、伴随文件和可见性策略。
# 审核后，将 REVIEWED_PLAN_ID 替换为该文件中准确的 plan_id。
python database.py --relink-photos --db library.db --config scoring_config.json \
  --apply-plan relink-plan.json --ack-plan REVIEWED_PLAN_ID \
  --acknowledge-unverified-identity
```

多用户模式下，在两条命令中都添加 `--user alice`。它用于选择检查哪位用户的范围，并非访问控制。规则：

- 两条路径对该用户都必须可见。
- 能够看到该照片的**所有**用户的集合必须保持不变。从私有移到共享，或其他跨用户移动，均会被拒绝。
- 两条路径都必须位于明确配置的扫描、用户或共享目录内。
- 空白的根目录配置、无法访问的根目录以及 `viewer.path_mapping` 均会被拒绝。只支持本机规范路径。

应用操作会在同一个数据库事务内重新检查整个计划。如果目标文件、照片记录、标注、数据库结构、数据库文件或可见性发生了变化，请重新预览。批次失败时，其所有数据库写入都会回滚。应用成功后会输出带有计划 ID 的回执。

## 哪些内容会随照片保留

以下内容会保留与照片的关联：

- 照片 ID、评分、Keep 和 GPS
- 标签、人脸、人物 ID 和手工人脸 UUID
- 比较记录、学习得分和各用户偏好
- 覆盖设置、固定的相册成员、封面和客户挑选
- 提取快照和向量嵌入
- 连拍、重复和序列组的值

派生统计会失效；训练状态则会保留。

不会改变的内容：

- **撤销历史**保留其旧路径。重新关联后，指向旧路径的条目可能不再显示，也可能无法还原。
- **手工人脸矩形框**会保留，但标记为 `relink_unverified`。请打开编辑器，针对新画面逐个保存每个矩形框，之后它才能被导出或用于抑制检测结果。
- **Immich** 的推送和待处理状态保持不变；不会重新关联任何远程评分、相册或 UUID。同步之前请自行检查远程映射。
- **扫描失败历史、智能相册筛选条件和序列组键**不会被改写。

## 明确列出的伴随文件与拒绝情形

请自行列出伴随文件；该工具无法发现已从旧目录消失的 RAW 或 XMP 文件。伴随文件类型：

| 类型 | 文件 |
|---|---|
| `sidecar_full` | `photo.ext.xmp` |
| `sidecar_basename` | `photo.xmp` |
| `sidecar_facet` | `photo.ext.facet.xmp` |
| `raw` | 同一目录、主文件名相同的 RAW 配对 |

这些规则只检查所声明的关系，并不证明身份。已索引的 RAW 照片需要有各自的顶层条目，其标注才能得到保留。现有的伴随文件会被哈希，且保持不变。空的伴随文件列表并不证明不存在此类文件。

Facet 会拒绝：

- 目标位置上未列出的附属文件或 RAW 伴随文件，包括 Facet 回退包和大小写变体
- 多个 RAW 候选或归属不明的 XMP，例如 `IMG.CR2` + `IMG.CR2.jpg` + `IMG.CR2.xmp`，或 `IMG.CR2` + `IMG.CR2.facet.jpg` + `IMG.CR2.facet.xmp`，以及基本名、大小写或 Unicode 冲突
- 旧原图仍然存在的副本
- 缺失或不可读的旧上级目录
- 已有照片或依赖记录的目标
- 重复的映射、重复的照片内容或目标 inode
- 仅大小写或仅 Unicode 的重命名、符号链接，以及扩展名或格式的变化
- 解码后尺寸与已存储尺寸不一致的目标（尺寸已知时）

不会运行任何相似度或文件名搜索。

每批的限制：100 张照片、300 个明确列出的文件、每个文件 512 MiB、总计 2 GiB，以及 2 MiB 的 JSON 输入或计划。达到限制时请拆分批次。数据库写入是原子的，但其他应用仍可能改动这些文件，因此该任务必须离线运行。

> **警告：** 目录可读并不能证明存储已挂载。未挂载的卷可能看起来像一个空文件夹。计划会报告 `source_mount_status: not_verified`；在确认身份之前，请确认每个源文件确实已被移动。该命令不会检测所有离线卷的情形。

计划文件包含私密的完整路径和用户范围。在 POSIX 上，`--plan-out` 会以独占方式创建它们，权限为 0600。

| 选项 | 用途 |
|---|---|
| `--db` | 现有数据库 |
| `--config` | 解析后的配置 |
| `--user` | 多用户模式下必须指定已配置用户 |
| `--mapping` | 显式旧/新路径 JSON；预览模式 |
| `--plan-out` | 创建新的私密计划文件，不覆盖已有文件 |
| `--apply-plan` | 应用已审核的计划 |
| `--ack-plan` | 已审核计划的准确摘要 |
| `--acknowledge-unverified-identity` | 明确确认原图字节身份未知的操作 |
