## Objective + success criteria
- On `/persons`, `/albums`, `/stats`, `/map`, `/timeline*`, `/scenes`, `/compare`, `ui_get_context.page` is `{id, ...state}` with that page's user-visible filter state; on every other route (gallery, `/photo`, `/culling`, `/junk`, `/folders`, `/capsules`, `/merge-suggestions`, login) `page` is `null` and nothing else changes. The block holds scalars only (no photo or item lists).
- State is read live: change the persons search box, then `ui_get_context` returns the new `search`; leave the page and `page` is `null` (no stale state from a root filter service the page no longer shows).
- Size: scalars are about 300 bytes; path fields (`pair_a`, `pair_b`) are exempt from any cut, so `/compare` can add up to two full paths (4096 each); free-text fields (search) are cut at 200 characters.
- `ui_get_context.overlays` is a (possibly empty) array from `dialog | bottom_sheet | slideshow`, on every page.
- While `overlays` is non-empty, every UI tool that is not read-only (`annotations.readOnlyHint` false) answers `modal_open` with no side effect; the read-only UI tools (`ui_get_context`, `ui_get_selection`, `ui_get_gallery_view`) still answer. Server-driven shows (`search_photos` / `similar_photos` / `semantic_search` with `show=true`, the `auto_cull` dry run) are refused the same way and report `shown_in_tab.reason = "modal_open"`; the search or plan itself still succeeds.
- Adding a page costs one `registerPageContext(...)` call in its component; `ui-tool-handlers.ts` gains no per-page code.
- The refusal sentence reaches external `/mcp` clients (the registered MCP tool description), not only the tab's generated descriptor.
- Contract JSON, docs (7 languages) and tests move in the same change; `scripts/dump_ui_tools.py --check` is clean after every step.

## Design decision (recommended)
- **ONE generic mechanism: `PageContextService`** (root, `client/src/app/core/agent/page-context.service.ts`), sibling of `ViewActionRegistry`, with two registries.
  - Page: `register(id, read: () => Record<string, string|number|boolean|null>): () => void` (the unregister removes only if still current); `snapshot(): {id, ...state} | null` calls the single registered reader inside try/catch (a throwing reader yields `{id}`). Readers return plain scalars: non-scalar values are dropped, free-text strings cut at 200, path fields (`pair_a`, `pair_b`, any `*_path`) never cut. Helper `registerPageContext(id, read)` calls `register` and wires `DestroyRef.onDestroy`, so a page adds one line and cannot forget cleanup.
  - Overlay: `registerOverlay(kind): () => void` for components that own a modal not visible to `MatDialog` (the shared slideshow on init/destroy, the auto-cull confirm on show/hide); `overlays(): string[]` unions those with `'dialog'` when `MatDialog.openDialogs` has any entry other than `ConnectAssistantDialogComponent` (excluded by component type, unit-tested) and `'bottom_sheet'` when a sheet is open. Every other MatDialog blocks, including the shortcuts and edition dialogs (documented). CDK menus, selects, tooltips and snackbars are NOT gated.
- **Output shape: a single `page` key.** Keeps `gallery` / `culling` / `timeline` / `album_id` untouched, and a new page needs no schema change. Page ids: `persons`, `albums`, `stats`, `map`, `timeline`, `scenes`, `compare`.
- **Per-page payloads** (snake_case): `persons` `{search, sort, sort_direction, show_hidden}`; `albums` `{search, sort, type}`; `stats` `{tab (index), category, date_from, date_to}` (an index, not a label: labels are i18n strings and no tool switches them); `map` `{date_from, date_to}`; `timeline` `{date_from, date_to, sort}` (year/month/level stay in B's `timeline`); `scenes` `{album_id, total}`; `compare` `{tab, category, strategy, pair_a, pair_b, pair_loading}` where `tab` is `null` when no category is selected and the pair fields are `null`/`false` when the A/B tab is not mounted.
- **Refusal.** Every UI tool with `readOnlyHint` false (the existing `UiTool.read_only`, no new flag) answers `modal_open` while `overlays` is non-empty: `ui_navigate`, `ui_open_photo`, `ui_open_album`, `ui_select_photos`, `ui_clear_selection`, `ui_set_gallery_filters`, `ui_show_photos`, `ui_next_page`, `ui_show_comparison`, `ui_show_culling_group`, `ui_show_culling_plan`, `ui_suggest_culling`; a future tool refuses by default. Reasons: a navigation under a MatDialog closes it and discards a half-typed form; a selection change under the actions sheet changes what the sheet acts on; the slideshow's timers are released only by its own teardown. Server-driven shows go through those same tools, so they are refused too and report `shown_in_tab.reason = "modal_open"`.
  **Error code**: a NEW `modal_open` (reuse would mislead the model into retrying or navigating elsewhere). Cost: `TAB_ERROR_CODES`, the two equality specs, the `Error codes:` docs line and the `shown_in_tab` reason list in 7 languages, the generated JSON.
  **Where**: one check in `WebMcpToolRegistry.run()` (`webmcp-registry.service.ts`), after schema validation and before the handler, keyed on the contract's existing `annotations.readOnlyHint`. Order against D: `invalid_input`, then `modal_open`, then the handler's `unsaved_decisions` guard. Server write tools (`set_rating`, `batch_set_*`, `create_album`) never touch the view and are not gated. The assistant cannot close a user's dialog; the user's close restores normal behaviour.
  **One sentence, two surfaces**: the refusal wording ("Refused with `modal_open` while a dialog, bottom sheet or slideshow is open in the tab; read-only tools are not affected.") is one shared constant in `ui_tools.py`, appended to every non-read-only tool's description in BOTH the generated descriptor and the `register_ui_tools` MCP registration, so external clients see it.

## Open questions / risks
- Race: a dialog opens between the check and the handler's first `await`; accepted (advisory, not a lock).
- `MatBottomSheet` detection (ASSUMED above); no lint suppression allowed.
- A registered reader that throws (e.g. `abTab()` undefined before the A/B tab is first shown) must degrade, never fail `ui_get_context`.
- `ui_get_context` is called often by server tools (`tools_read.py:499`, `tools_culling.py:392,407`): the added work is O(1) signal reads plus `openDialogs.length`; no DOM query.
- `available_actions` facts (`actionFacts`, `ui-tool-handlers.ts:151`) are route-based and unchanged; an `actions` row disappearing under a modal is a separate decision.
- A tab older than the server omits `page` / `overlays` and cannot answer `modal_open`; docs say "absent from an older tab" (`tab_outdated` covers tool-version mismatch).
- Out of scope: the `/culling` list cursor (step 6), page blocks for `/junk`, `/folders`, `/capsules`, `/merge-suggestions` (each is a one-liner later), reporting a dialog's title.
